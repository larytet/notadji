# 33 - Firmware framework for the real-time control core

Source requirements: SW-001..SW-009, HSI-005..HSI-008, HSI-011, HSI-012, HSI-014, HSI-015, MAC-004, MAC-005, VID-006, THM-001..THM-003,
ANT-001..ANT-004, CAL-003, CAL-006, CAL-008, IF-001, MAC-007, SEC-001, SEC-003, SEC-005, SEC-006, SW-004, SW-005
(`spec/01-system-requirements.md`). Design and test plan: `design/33-firmware-framework.md`. Code: `fw/33-framework/`. Tests: `tests/33-firmware/`.

## 1. Review of the existing requirements (what was changed, and why)

| Finding | Action |
|---|---|
| SW-001 said "Linux (or Zephyr/RTOS) on the application CPU", while HSI-001 and `13` put the control loops on hard real-time cores and make Linux optional. The two contradicted each other. | SW-001 reworded: control plane on the real-time core(s), Linux optional and outside the real-time path. |
| HSI-006 asks for worst-case execution times measured on the target core. No target core exists before phase A. | HSI-006 split in two: the host phase records per-task maxima in the scheduler cycle accounting and the static AArch64 stack and code size; the trace-port measurement stays a phase A/B item. |
| Nothing said how firmware is written (allocation, interrupt rules, word size). The target is a 64-bit ARM core (Cortex-A53 class on the phase B device, R-class cores are 32-bit). | SW-006 added: static allocation, bounded loops, LP64-clean, same source for x86-64 host and AArch64 target, warnings are errors. The framework therefore avoids `long` and pointer-size assumptions and uses C11 atomics for cross-core queues. |
| HSI-011 says the sequencer detects a stalled control core and falls back to a safe schedule. The sequencer RTL (module 10) replays the last committed table and counts `missed`; `force_safe` turns every line off (SAFE_LINES), which stops the video. It does not switch to the lowest MCS. | Not changed in RTL. Firmware side added (SW-007, R33-12): a monitor on a second core watches the heartbeat and `missed`, and commits a pre-built safe table. Open item for module 10: a hardware safe-table bank. |
| SW-005 asks for logging that survives a crash but not for the record layout, size or torn-write behaviour. | R33-05 defines them. |
| SEC-003/005/006 say "signed" with no algorithm. IF-001 says "MSP, MAVLink 2" without framing details. SEC-001 does not say how the short code authenticates. | SW-009 and SW-008 added; R33-09..R33-11 give the algorithms (Ed25519, X25519 with a transcript-derived short code, CRC-16/MCRF4XX and CRC-8/DVB-S2). |
| MAC-005 gives 2 ms from feedback to a changed MCS but the feedback message format is nowhere defined. | R33-07 defines the uplink feedback message (module 33 design section 5). |

Systems requirements added to `spec/01-system-requirements.md`: SW-006, SW-007, SW-008, SW-009 (the trace matrix was regenerated).

## 2. Module requirements

| ID | Requirement | Acceptance criterion | Source |
|---|---|---|---|
| R33-01 | HAL: all hardware access through `hal_ops` (register read/write, cycle counter, retained RAM, flash, random source, watchdog kick) and a versioned register map `regmap.h`; a host simulation backend implements the same interface. | No firmware file other than `hal_*.c` includes a platform header; the simulated sequencer backend reproduces bank, commit, frame and `missed` semantics of module 10. | SW-002, SW-003, HSI-012 |
| R33-02 | Static scheduler: periodic tasks with period, deadline, cycle budget and priority; deferred interrupt handlers; no heap. | Task order by priority at equal release; no task released twice for one period; budget overruns and deadline misses counted per task; load figure computed over a window; tasks may not be registered at run time after `sched_start`. | SW-006, HSI-005, HSI-006 |
| R33-03 | Worst-case accounting: per-task maximum and mean cycles, overrun and miss counters, stack high-water, readable through a status struct. | The accounting equals an independent count of the consumed cycles in the test; the load at the 1080p120 task set of `13` section 2 is at most 50% on a 300 MHz model core. | HSI-005, HSI-006 |
| R33-04 | Non-blocking cross-core queues (single producer, single consumer, power-of-two, C11 acquire/release) and a mailbox for latest-value data. | Two-thread stress test with 10^7 items loses, duplicates or reorders nothing; push on full and pop on empty return at once; no lock in the code path (checked by inspection: no loop depends on the other core). | HSI-014 |
| R33-05 | Crash log: fixed 32-byte records (sequence, time, type, 3 arguments, CRC-16) in a ring in retained RAM, written at 1 kHz; recovery after reset finds all valid records in order. | Reset at any byte of any write: recovered records are a gap-free prefix of the written ones (at most the one record in progress is lost); wrap-around keeps the newest N; 1000 records per second for 60 s use at most 1 ms of cycle budget per second on the model core. | SW-005 |
| R33-06 | Supervision: tasks check in; a task with three overruns in a row or a missed deadline is recorded in the crash log and the safe schedule is requested; the hardware watchdog is kicked only when all supervised tasks have checked in in the period. | Fault-injection test: stall of each task kind produces the log entry, the request and the missing kick within the specified number of periods; no spurious request in 10^6 normal periods. | SW-007, HSI-011 |
| R33-07 | MAC feedback path: parse the uplink feedback message (CSI summary, MCS recommendation, RSSI, per-slice ACK bitmap, CRC-16) and apply `link_adapt`; commit the new MCS, power and slice budget to the sequencer and modem registers. | From the feedback message in the receive buffer to the register commit: at most 2 ms (counted on the model core, 300 MHz) for the worst message; corrupt messages are dropped and counted. | MAC-004, MAC-005 |
| R33-08 | Rate retarget: per-slice byte targets from the slice budget, the thermal bitrate factor and the telemetry share, updated per frame. | The sum of targets never exceeds the budget; an increase of the thermal step reduces the targets within one frame; 8 slices at 120 fps cost at most 4000 cycles per frame (the estimate of `13`). | VID-006, THM-003 |
| R33-09 | Thermal and RF protection: four temperature sensors (0.25 deg C), throttling steps (TX power, video bitrate, frame rate, shutdown) with configurable thresholds and hysteresis; VSWR from forward and reflected power; fold-back above 3:1 by 6 dB, shutdown above 6:1 within 1 ms, automatic recovery; power control loop; recalibration triggers (5 deg C, 60 s, VSWR change of 0.5). | VSWR error at most 0.3 at 3:1 over 1 to 10:1 (fixed point against floating point); shutdown reached in at most one 1 ms control period after the sample exceeds 6:1; power loop settles within 100 us (10 steps of 10 us) for a 3 dB step; a failed sensor (out of range or stuck) is treated as hot. | THM-001..003, ANT-001..004, CAL-003, CAL-006, CAL-008 |
| R33-10 | Host protocol parser: MAVLink 2 (CRC-16/MCRF4XX with CRC extra, optional signature skipped) and MSP v1 and v2 (CRC-8/DVB-S2) from a DMA ring, bounded work per call, resynchronisation. | CRC check values equal the published ones; 10^5 random frames with random garbage between them are all recovered; a corrupted byte loses only the frame containing it; at most N bytes consumed per call. | SW-008, IF-001, MAC-007 |
| R33-11 | Security: SHA-256, SHA-512, HMAC and HKDF; X25519 pairing with a six-digit short code derived from the transcript and no default key; Ed25519 verification of images and tables; region limiter from a signed table. | RFC 7748, RFC 8032, RFC 5869 and FIPS 180 vectors pass; cross-check against an independent library on random inputs; a pair of devices agrees on keys and code, an active man in the middle gives different codes; any single bit change of a signed table or image is rejected; the limiter never lets a request above the signed limit through. | SEC-001, SEC-003, SEC-005, SEC-006, SW-009 |
| R33-12 | Dual-slot update and safe schedule: A/B images with header, chunked transfer with resume, trial boot with a counter and rollback, anti-rollback version; monitor core that commits the safe table when the main core's heartbeat stops for two frames. | Power cut at every flash operation of an update: the next boot always selects a valid, signed image; a bad image never becomes active; the monitor commits the safe table within three frames of a stall and never when the heartbeat is alive. | SW-004, HSI-011, SEC-003 |
| R33-13 | Portability: every file builds with `-std=c11 -Wall -Wextra -Wconversion -Werror` for x86-64 (tests) and for AArch64 (clang, freestanding, compile-only); the tests run under AddressSanitizer and UBSan; the object sizes are recorded. | Both builds clean; the sanitizer runs report nothing. | SW-006 |

## 3. Out of scope for this module

Linux application core services (web/API, recording, OSD); the hardware-locked region limiter in silicon (SEC-005, only the firmware side is here);
running on a real or emulated AArch64 core (no cross linker or QEMU on the build host, so AArch64 is a compile check only); the MPU configuration (HSI-015, a target item that depends on the core);
ISR entry latency (HSI-008, measured on the target only).
